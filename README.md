# diamond-gdspy-cc2020
# Nanobeam Optomechanical Crystal (OMC) GDS Layout Generator

This repository contains a `gdspy`-based toolkit for generating GDSII layout
files for suspended photonic-crystal nanobeam optomechanical devices
("OMCs"), along with associated alignment markers, text labels, and support
structures (cantilevers, tethers, ZEP exposure boxes). It is organized as a
small library of geometry-generating modules plus top-level "array" scripts
that assemble full device arrays into a single GDS file for fabrication.

## Overview

Each device is a suspended nanobeam consisting of a 1D photonic crystal
(PhC) cavity flanked by mirror/waveguide-mode-matching hole tapers, clamped
at one end and terminated at the other end by a tapered fiber-coupling
waveguide. Devices are parameterized by hole geometry (lattice constant,
hole size, ellipticity, defect taper), device dimensions (waveguide widths,
clamp/support lengths), and global/local scaling factors, so that a single
array script can sweep a small set of design parameters (e.g. number of
mirror holes, PhC scaling factor) across a 2D grid of devices on one chip.

The array scripts:
- compute a test device to determine the longest device length (so column
  spacing and PhC length can be fixed across the sweep),
- loop over the parameter sweep to instantiate devices into per-column
  cells, replicate each device several times per row,
- add text labels identifying each row/column's parameter values,
- add corner alignment markers,
- and write everything out to a single `.gds` file.

## Device Geometry

Each device is built left-to-right along the x-axis as a `gdspy.Path`,
conceptually in four sections:

1. **Clamp** — a wide, mechanically anchored region. A straight segment at
   `clp_wid` width (`clp_strlen`), then a linear taper down to the waveguide
   width `wg_wid` (`clp_taplen`), then a short straight run-out
   (`clp_outlen`) before the photonic crystal begins.

2. **Photonic crystal (PhC)** — a 1D array of elliptical holes etched into
   the nanobeam, generated by `holes.py`. The crystal is built from three
   kinds of hole segments, assembled left-to-right around a center hole:
   - a tapered **defect** region (`ndef` holes, taper function `taper_func`,
     max lattice-constant defect `maxdef`) that forms the optical cavity,
   - constant-period **mirror** regions on the left and right
     (`nmirL`/`nmirR` holes) that confine the optical mode,
   - a **waveguide-mode-matching taper** on the right (`nwgm` holes, tapering
     from mirror hole parameters `a, hx, hy` to waveguide parameters
     `aW, hxW, hyW`) that couples the cavity mode into the output waveguide.
   `holeinctr` controls whether a hole or solid dielectric sits exactly at
   the crystal's center. `phc_scl` applies a local, uniform scale factor to
   `a`, `hx`, `hy`, and `wg_wid` for this section only, letting you sweep
   the PhC's resonant frequency without changing the rest of the device.

3. **Tapered support** — added by `geom.add_tapsup_to_beam()`. A straight
   run (`out_len`) at the PhC's waveguide width, a quadratic taper up to a
   wider "paddle" width `tapsup_wid` (`tapsup_len`), an optional straight
   center section (`ctr_len`), then a quadratic taper back down to
   `in_wid` (`tapsup_len`) and a straight run-in (`in_len`). This wider
   section is typically where mechanical tethers are attached, and/or where
   the beam is easiest to probe optomechanically. In the ZEP variant,
   `geom.add_tethers_to_tapsup()` adds a comb of tether rectangles
   (`n_tets`, `w_tets`, `l_tets`, `g_tets`, `tets_side`) straddling this
   section to anchor the suspended beam to the surrounding substrate.

4. **Waveguide taper** — a final linear taper from the support's input
   width out to a narrow tip (`end_wid`) over length `end_len`, used for
   fiber/lensed-fiber edge coupling.

A global `wid_corr` offset is added to all waveguide-region widths to
compensate for lateral erosion during angled-etch fabrication.

The ZEP variant (`devices_zep.py`) additionally wraps the whole device in a
rectangular "ZEP box" (`zepbox_wid`) on a separate layer, marking the region
to be exposed/cleared for suspended release, and adds the tether structures
described above.

## Modules

| File | Role |
|---|---|
| `holes.py` | Core PhC hole geometry: `calc_phc_holes` (tapered defect/mirror hole arrays), `calc_wgm_holes` (waveguide-mode-matching taper), `calc_phc_holes_lr` (assembles left+right hole segments into one crystal about a center hole), `add_holes_to_cell` (draws holes as `gdspy.Round` polygons), `taper_function` (cubic/quadratic/linear/none taper profiles). |
| `geom.py` | Beam geometry helpers: `add_tapsup_to_beam` (appends the tapered-support segments to a `gdspy.Path`), `add_tethers_to_tapsup` (adds tether rectangles around a given x-center). |
| `devices.py` | Device assembly for **rectangular/plain** nanobeams: `dev_clp_phc_tsp_twg` (clamp + PhC + tapered support + waveguide device) and `cantilever` (a simpler clamp + straight beam test structure). |
| `devices_zep.py` | Device assembly for the **ZEP/tethered** variant: `dev_clp_phc_tsptets_twg_zep`, same device as above but adds tethers and a surrounding ZEP exposure box. |
| `markers.py` | `sq4_markers`: generates 4-square alignment marker cells (large/small squares in TR/BL and TL/BR quadrants with a small central gap), for e-beam/optical alignment between layers. |
| `layerdefs.py` | Central GDSII layer/datatype assignments (`wgspec`, `holespec`, `clmpspec`, `markspec`, `lablspec`, `aperspec`, `mclrspec`, `zepspec`) shared by all modules — edit this file to change which GDS layer a feature is drawn on. |
| `20200101triOMCarray.py` | Array script for triangular-waveguide OMC devices (uses `devices.py`). Sweeps `nmirR` × `phc_scl`, arranges devices in a labeled grid, adds corner markers, writes GDS. |
| `20200102rectOMCarrayZEP.py` | Array script for rectangular-waveguide OMC devices with ZEP tether boxes (uses `devices_zep.py`). Same sweep/labeling/marker structure, additionally rotates each column by 45° increments and sizes column spacing/markers for the wider ZEP boxes. |
| `20200104tri45oIBEtest.py` | Array script combining OMC devices (`devices.py`) with cantilever test structures (`cantilever` in `devices.py`), sweeping `nmirR` × `phc_scl` × cantilever width, and placing cantilevers alongside the main device array. |

All three array scripts follow the same pattern and can be used as templates
for a new sweep — the differences are mainly which device-generating
function is imported, which parameters are swept, and how cantilevers/
tethers/rotation are added.

## Dependencies

- Python 3
- [`gdspy`](https://github.com/heitzmann/gdspy) — GDSII layout creation
  (note: these scripts use the `gp.current_library` / `GdsLibrary.new_cell`
  API style typical of older `gdspy` versions; check compatibility if using
  a recent `gdspy` release)
- `numpy`

The array scripts call `os.startfile(gdsname)` at the end to auto-open the
generated GDS in the OS default viewer — this is **Windows-only**; comment
it out (or replace with your platform's equivalent) on macOS/Linux. Opening
in [KLayout](https://www.klayout.de/) is recommended.

## Usage

To generate a device array GDS file:

1. Make sure `gdspy` and `numpy` are installed, and that all module files
   (`holes.py`, `geom.py`, `devices.py`, `devices_zep.py`, `markers.py`,
   `layerdefs.py`) are on your Python path alongside the array script you
   want to run.
2. Open the array script (e.g. `20200101triOMCarray.py`) and edit:
   - `geom0` — nominal device geometry (hole/lattice parameters, waveguide
     widths, taper lengths, etc.)
   - `nmirR_all`, `phc_scl_all` (and, for the test script, `cant_wid`) — the
     parameter values to sweep across the array
   - `nreps`, `row_sp`, `row_offset` — replicate count and array spacing
   - `gdsname` — output filename
3. Run the script:
   ```bash
   python 20200101triOMCarray.py
   ```
4. The script will:
   - build a test device to size column spacing and fix the PhC length,
   - generate one cell per (mirror count, scaling factor) combination,
     replicated `nreps` times per column,
   - add `M<n>` and `S<n>` text labels identifying mirror count and scaling
     factor for each row/column,
   - add 4 corner alignment markers,
   - write the full layout to `<gdsname>.gds`,
   - print the top-level and full cell list to the console,
   - and open the resulting GDS file (Windows only, via `os.startfile`).

To adapt one of these scripts for a new device design, swap the imported
device-generating function (`dev_clp_phc_tsp_twg` vs.
`dev_clp_phc_tsptets_twg_zep`) and adjust `geom0` accordingly — the array
assembly logic (column/row placement, labeling, markers) can typically be
reused unchanged.
